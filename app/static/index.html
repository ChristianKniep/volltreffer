Setup & usage

Run the stack locally and connect it to your teamtip round

1 · Run the docker-compose stack

You need Docker with the Compose plugin. From the wc2026-app/ folder:

cd wc2026-app
docker compose up -d --build

Then open http://localhost:8000. The app seeds the schedule, predictions and bracket automatically on first start.

  • The SQLite database lives in the named volume wc2026-data (mounted at /data), so results and synced tips survive restarts and rebuilds.
  • The source folder is bind-mounted (./app:/srv/app), so edits to the static files show up on a browser reload; Python changes need docker compose restart wc2026.
  • Enter results by clicking any match and filling in the score, or wire up an automatic feed via FIXTURES_URL / FOOTBALL_DATA_TOKEN in docker-compose.yml.

Useful commands:

docker compose logs -f wc2026      # follow logs
docker compose restart wc2026      # reload after a Python change
docker compose down                # stop (keeps the data volume)
curl -X POST localhost:8000/api/reset   # wipe & re-seed the DB

2 · Create your account

The app is multi-user. On first start an admin account is created from ADMIN_USER / ADMIN_PASSWORD in docker-compose.yml (default admin / admin — change it). Everyone else can self-register from the login screen unless you set ALLOW_REGISTRATION: "false". Each account has its own tips and its own betting-backend credentials.

Set a strong APP_SECRET_KEY in docker-compose.yml — it encrypts every stored credential. Changing it later makes already-saved credentials unreadable (users just re-enter them).

3 · Connect a betting backend (Settings tab)

Betting sites are plugins. Open the Settings tab, pick a backend, fill in its fields and Save. For teamtip.net you need a bearer token plus your user and betgame IDs:

  1. Log in at teamtip.net in your browser.
  2. Open DevTools (F12 / Cmd+Opt+I) → Network tab.
  3. Trigger a request to /bg_bet — e.g. open or refresh your tips/round page.
  4. Click that bg_bet request → Headers → Request Headers, and copy the full authorization value (Bearer eyJ…).
  5. Paste it into the Bearer token field in Settings, add your user / betgame IDs, and Save & test.

The token expires periodically — when sync reports it was rejected, grab a fresh one and re-save (leave other fields as-is). Synced tips are stored in the database and stay visible in the Groups overview (Tip column) even after the token later expires.

Click Update results in the header to fetch finished games and sync every backend you've connected in one go. The Tips selector next to it chooses which backend's tips are shown when you have more than one.

Credentials live encrypted in the database, scoped to your account — not in docker-compose.yml. The legacy TEAMTIP_TOKEN env var is still read once on first start and imported onto the admin account, so you can delete it from compose afterwards.

4 · Update your predictions with an agent (skill)

Each match shows a model prediction. You can revise the prediction in your own view — for example after a matchday, feeding in news and reasoning — using the my-predictions skill from any agent harness (Claude Code, the Claude Agent SDK, etc.). Your changes are private to your account and never touch the shared model or your betting tips.

  1. Get your token. On the Settings tab, click Generate under Personal API token and copy it.
  2. Install the skill. It ships in the repo at skills/my-predictions/ (a SKILL.md + a dependency-free my_predictions.py client). Point your agent at that folder — e.g. for Claude Code, copy it under .claude/skills/ in your project, or pass the path to the Agent SDK.
  3. Configure it with two environment variables:
export VOLLTREFFER_URL="http://localhost:8000"
export VOLLTREFFER_TOKEN="vt_…"      # the token from Settings

Then talk to your agent about the matches and let it write your predictions back. Example prompt:

Using the my-predictions skill, let's review Group C after matchday 2.
Here's the coverage I gathered: <paste articles / notes>.

Go match by match through my upcoming fixtures. For each, tell me the
current prediction, weigh the news (injuries, form, must-win context),
and propose a revised scoreline with a one-line rationale. When I agree,
update my prediction for that match. Afterwards, show me the diff.

The agent reads your view via GET /api/state, then calls POST /api/match/<id>/my-prediction with the new scoreline (and optional rationale) for each match you approve; DELETE on the same path reverts a match to the model. Match IDs are G01–G72 (group) and M73–M104 (knockout). Revised matches show a small your view marker.

Using OpenCode? skills/OPENCODE.md has a copy-paste setup to run the skill from an empty directory (drop it in .opencode/skills/, export VOLLTREFFER_URL/VOLLTREFFER_TOKEN, run opencode).
